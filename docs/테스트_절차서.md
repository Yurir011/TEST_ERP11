# BENCH ERP 통합 테스트 절차서

- 문서 버전: v1.0
- 작성일: 2026-10-01
- 테스트 대상: 1~17단계 완료 기능 전체 (CLAUDE.md 기준)
- 관련 단계: `18단계 — 통합 테스트 및 사용자 피드백`

---

## 1. 목적 및 범위

구현이 완료된 전체 기능(로그인/권한, 대시보드, 일정관리, 전자결재(문서관리·연차관리·증빙서류발급), 프로젝트관리, 거래처관리, 세금계산서, 매입매출관리, 입출금관리, 업무알림, 출퇴근, 직원등록)을 역할별(관리자/일반직원)로 1회 전수 점검하여, 2차 피드백 수집 및 사내 배포 전 결함을 조기 발견하는 것을 목적으로 한다.

범위에서 제외: 홈택스 실연동(16단계 보류), OCR 영수증 자동인식(17단계 보류) — 수기/CSV 대체 기능만 테스트.

---

## 2. 테스트 환경 준비

### 2.1 실행 체크리스트

- [ ] PostgreSQL 서비스 기동 확인 (`erp_db`, 계정 `erp_user`)
- [ ] `backend/.env` 값 확인 (DB 접속정보, `LOG_LEVEL=DEBUG`로 설정해 디버그 로그 노출)
- [ ] 백엔드 실행: `start.bat` 또는 수동 실행 후 http://localhost:8000/api/health 200 OK 확인
- [ ] 프론트엔드 실행: http://localhost:5173 접속 확인
- [ ] 백엔드 콘솔창(또는 로그 파일)과 브라우저 개발자도구 콘솔을 테스트 내내 띄워 둘 것 — 각 시나리오 수행 시 `[모듈명] ...` 형식 디버그 로그가 실제로 출력되는지 함께 확인한다 (코딩 규칙 준수 여부 점검 겸함)

### 2.2 테스트 계정

아래 3종 역할 계정을 최소 1개씩 준비한다 (기존 계정 사용 또는 `backend/app/scripts/create_admin.py`, `create_site_admin.py` 로 생성).

| 역할 | 설명 | 비고 |
|---|---|---|
| 대표/관리자 (`admin`) | 전 메뉴 접근, 직원등록 가능 | 일반 대시보드 사용 |
| 일반직원 (`employee`) | 관리자가 부여한 `menu_permissions` 에 따라 메뉴 노출 상이 | 최소 2개 계정(권한 다르게 부여) 권장 |
| 사이트 관리자 (`site_admin`) | 별도 대시보드(`SiteAdminDashboardPage`) 사용 | 공지/일정은 관리자 권한과 동일 취급 |

### 2.3 테스트 데이터

- 거래처 2건 이상 (사업자번호/담당자/연락처 상이)
- 진행 단계가 다른 프로젝트 2건 이상 (견적/진행/완료)
- 연차 신청 가능한 재직기간을 가진 직원 계정 1개
- 카드 명세서 CSV 샘플 파일 1개 (입출금 가져오기용)
- 영수증 이미지 1장 (jpg/png)

## 3. 결과 기록 규칙

각 시나리오의 **결과** 칸에 `P`(Pass) / `F`(Fail) / `B`(Block) 로 기록하고, Fail/Block 건은 하단 "6. 결함 기록"에 별도로 남긴다. 테스트는 아래 순서(①공통 → ②관리자 권한 → ③일반직원 권한)대로 진행한다.
