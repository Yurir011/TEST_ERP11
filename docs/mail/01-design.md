# 메일 기능 설계서 (로컬 메일 클라이언트형)

> 2026-10-17 작성 · 개정 2회(로컬형으로 변경) · 상태: **설계 검토 완료, 구현 전**
> 대상 버전: V.0.71.001 (DB 표를 추가하면 "부" 자리를 올린다. [버전 규칙](../version-policy.md))
> 메일 서비스: 다음 스마트워크 — IMAP 993/SSL, SMTP 465/SSL (서버 주소는 사용자가 관리자 콘솔에서 확인)

## 1. 확정된 결정

| # | 결정 | 의미 |
|---|---|---|
| 1 | **메일은 데스크톱 앱에서만 쓴다** (썬더버드형) | 앱이 IMAP/SMTP 에 직접 접속하고 메일을 그 PC 에 보관한다. 브라우저에서는 메일을 읽거나 보낼 수 없다 |
| 2 | **웹에는 안 읽은 메일 수만 표시** | 앱이 숫자만 서버에 알린다. 제목·발신자·본문은 서버로 보내지 않는다 |
| 3 | **문서 발송은 해당 직원의 계정으로** | 그 직원 PC 의 앱에 등록된 계정으로 보낸다. 공용 계정·서버 발송은 만들지 않는다 |
| 4 | **웹에서는 발송하지 않는다** | 문서 화면의 [메일 보내기]는 앱에서만 동작하고, 브라우저에서는 "데스크톱 앱에서 사용할 수 있습니다"로 안내한다 |
| 5 | 서버는 메일 비밀번호·본문·첨부를 보관하지 않는다 | 비밀번호는 PC 의 Windows 암호화 저장소(Electron `safeStorage`)에만 둔다 |

## 2. 범위

| 단계 | 내용 | 서버 DB 변경 |
|---|---|---|
| **M1 읽기** | 계정 등록, 폴더·목록, 본문·첨부 보기, 읽음 표시 | 없음 |
| **M2 쓰기·보내기** | 새 메일, 답장, 전달, 첨부, 보낸편지함 | 없음 |
| **M3 편의** | 검색, 새 메일 알림(IDLE), 안 읽은 수 배지, 삭제/휴지통 | 없음 |
| **M4 ERP 연동** | 문서 화면 [메일 보내기] → 앱의 작성 창에 PDF 첨부·거래처 주소 채움, 웹에 안 읽은 수 표시, 발송 이력 | 아래 3장 (승인 대기) |

M1~M3 는 서버를 건드리지 않는 앱 안의 기능이라 서버·DB 위험이 없다. 서버 연동은 M4 에서만 한다.

## 3. 서버에 두는 것 (M4) — 승인이 필요한 항목

| 항목 | 방법 | DB 변경 | 비고 |
|---|---|---|---|
| 안 읽은 메일 수 | 앱이 `PUT /api/mail/unread` 로 `{count}` 를 올린다(로그인 토큰 기준, 본인 것만). 웹이 `GET /api/mail/unread` 로 본인 값을 읽는다 | **없음 권장** — 서버 메모리에 보관(재시작하면 다음 보고 때까지 0). 앱은 변할 때와 몇 분마다 보고 | 영속이 필요하면 표 1개(`mail_unread`)로 바꿀 수 있다 |
| 발송 이력 | 앱이 보낸 직후 `POST /api/mail/sent` 로 `{doc_type, doc_id, to[], subject}` 를 알린다 | **있음 — `mail_logs` 표 1개 신설(리비전 0010)** | 문서 화면에 "누가 언제 누구에게 보냈는지"를 보이기 위함. 본문·첨부 내용은 저장하지 않는다 |

- **승인 요청: `mail_logs` 표 신설.** 기존 표 변경·데이터 삭제 없음. 컬럼: id, created_at, sender_user_id(FK users, 삭제 시 SET NULL), doc_type, doc_id, to_addresses, subject. 인덱스 `(doc_type, doc_id)`. 이력이 필요 없다면 이 표 없이도 나머지 모두 동작한다.
- 이력은 **앱이 알려 주는 값**이라 위조될 수 있다(자기 이력만 기록, 신뢰 수준은 "참고용"). 서버 권한 확인: 그 문서를 볼 수 있는 직원만 기록 가능.
- 안 읽은 수는 사용자 본인만 읽고 쓴다(다른 직원 것 접근 불가, 대표도 불가).

## 4. 보안 원칙

- 메일 비밀번호(또는 앱 비밀번호)는 앱에서 입력받아 `safeStorage` 로 암호화해 PC 에만 저장한다. 서버로 보내지 않고, 로그·화면·변경 이력에 남기지 않는다. 암호화 저장소를 쓸 수 없는 PC 에서는 저장을 거부하고 안내한다(평문 저장 금지).
- 채팅·문서에 비밀번호를 적지 않는다. 사용자 입력은 앱 화면에서만.
- **메일 처리는 Electron 메인 프로세스에서만** 한다. 화면(렌더러)은 IPC 로 요청하고, 비밀번호는 렌더러로 전달하지 않는다. IPC 는 기존처럼 발신자 출처를 검사한다(`classifySender`).
- **HTML 메일은 격리해서 표시**한다: sandbox 처리된 별도 보기, 스크립트·외부 리소스(원격 이미지·폰트·iframe) 기본 차단 ("이미지 보기" 선택 시 허용), 링크는 앱 안에서 열지 않고 확인 후 기본 브라우저로. 가장 중요한 보안 지점이라 별도 테스트를 둔다.
- 첨부 열기: 임시 폴더에 저장 후 열기, 실행 파일 확장자는 경고. 저장 위치는 사용자가 고른다.
- 보내기: 받는 주소 형식 검증, 헤더 인젝션(줄바꿈) 방지, 첨부 크기 제한(서비스 한도 확인 후).
- 로컬 저장소(SQLite)는 사용자 데이터 폴더에 두고, 앱 삭제 시 남는다는 안내를 한다. 퇴사·분실 PC 는 계정 비밀번호 변경으로 대응(서버 쪽에서 막을 방법이 없음 → 한계로 문서화).
- 개발·테스트는 가짜 IMAP/SMTP 서버로만 한다. 실제 서버 접속은 사용자가 직접 확인한다.
- 모든 새 코드에 `[Mail] ...` 접두사 디버그 로그(프로젝트 코딩 규칙). 로그에 비밀번호·본문은 남기지 않는다.

## 5. 구현할 일

### 5.1 앱 (desktop/) — M1~M3
1. 의존성: `imapflow`(IMAP), `mailparser`(해석), `nodemailer`(SMTP), SQLite(`better-sqlite3` 또는 Electron 호환 대안). **네이티브 모듈 여부를 먼저 검증** — 이 프로젝트는 `npmRebuild:false` + `asarUnpack` 구성이라 네이티브 모듈이 설치 파일에서 동작하는지 PoC 로 확인한다(M0).
2. `src/mail/account.ts`: 계정 설정(IMAP/SMTP 호스트·포트·SSL, 사용자, 비밀번호 `safeStorage`), 연결 테스트.
3. `src/mail/sync.ts`: 폴더 목록, 증분 동기화(UID 기준), 연결 끊김 복구, IDLE 새 메일 감지, 오래된 메일 가져오기 범위 설정(예: 최근 90일 기본).
4. `src/mail/store.ts`: 로컬 SQLite(메일 헤더·본문·첨부 메타·읽음·폴더), 검색용 색인.
5. `src/mail/send.ts`: 작성·답장·전달, 첨부, 보낸편지함에 복사(IMAP APPEND).
6. `src/mail/html.ts`: HTML 정리·격리 표시.
7. `src/main.ts`/`preload.ts`: `window.benchDesktop.mail.*` IPC (목록·본문·읽음·보내기·계정), `nfcMode` 처럼 허용 출처 검사.
8. 알림: 새 메일 시스템 알림(메신저 알림과 같은 방식), 트레이·작업 표시줄 배지는 메신저와 합산할지 분리할지 결정 필요.
9. 테스트: 파서·동기화·저장소·HTML 정리·IPC 검증 단위 테스트, 가짜 IMAP/SMTP 로 앱 smoke 확장.

### 5.2 화면 (frontend/) — M1~M4
1. 메일 페이지(앱에서만 메뉴 표시): 폴더 | 목록 | 본문 3단 레이아웃, 작성 창. 브라우저 접속 시 메뉴 대신 "앱에서 사용" 안내와 **안 읽은 수** 배지.
2. `lib/desktop.ts` 에 메일 브리지 타입 추가. 앱 여부로 기능 분기.
3. 문서 화면(견적서·거래명세서·세금계산서·증명서) [메일 보내기] 버튼: 앱이면 작성 창을 열고 **PDF 를 첨부 + 받는 주소(거래처·담당자 이메일) 후보를 채움**, 브라우저면 비활성 + 안내.
4. 문서 상세에 "발송 이력"(M4, `mail_logs` 승인 시).
5. 주요 이벤트에 `console.debug("[Mail] ...")`.
6. 테스트: 앱/브라우저 분기, 안 읽은 수 표시, 버튼 상태.

### 5.3 서버 (backend/) — M4
1. `routers/mail.py`: `PUT/GET /api/mail/unread`(메모리), `POST /api/mail/sent`, `GET /api/mail/logs?doc_type=&doc_id=`.
2. (승인 시) 리비전 `0010_mail_logs`, 모델 `mail_log.py`.
3. 문서 PDF 는 기존 다운로드 엔드포인트를 앱이 로그인 토큰으로 받아 첨부한다(**새 PDF 생성 로직 없음**).
4. 테스트: 본인 외 접근 불가, 권한 없는 문서 기록 거부, 입력 검증, 이력 조회, 비밀 값 비노출.

### 5.4 문서·배포
- `docs/mail/02-…` 단계별 결과 문서, 사용 설명서에 "메일" 절(계정 등록 방법, 앱 비밀번호 안내 포함), CHANGELOG, README 갱신.
- 운영 반영: M1~M3 는 앱 설치 파일만 배포(서버 변경 없음). M4 는 DB 백업 → `alembic upgrade head` → 서버 배포 순서.

## 6. 작업 순서 제안
1. **M0 PoC**: 네이티브 모듈(SQLite)과 IMAP 접속이 설치 파일 안에서 동작하는지, 다음 스마트워크 접속·인증 방식(앱 비밀번호/2단계) 확인. 사용자 계정으로 실제 접속하는 부분은 사용자가 직접 앱에서 입력한다.
2. M1 → M2 → M3 순서로 앱 기능, 각 단계마다 테스트와 문서.
3. M4 서버 연동(`mail_logs` 승인 후).

## 7. 위험과 대응
| 위험 | 대응 |
|---|---|
| 다음 스마트워크가 OAuth/앱 비밀번호만 허용 | M0 에서 먼저 확인. OAuth 만 가능하면 방식 재검토 |
| 네이티브 모듈이 설치 파일에서 동작 안 함 | 순수 JS 저장소(파일 기반)로 대체 |
| HTML 메일의 악성 내용 | 격리 표시·외부 리소스 차단·링크 확인, 변형 테스트 |
| 대용량 사서함 동기화 지연 | 기간 제한, 증분 동기화, 첨부는 필요할 때만 내려받기 |
| 분실·퇴사 PC 의 로컬 메일 | 서버에서 막을 수 없음. 비밀번호 변경·PC 보호(디스크 암호화) 안내 |
| 이력이 앱 보고 기반(위조 가능) | 참고용으로 명시. 실제 증빙은 메일 서버의 보낸편지함 |

## 8. 사람이 직접 확인할 것 (구현 후)
1. 앱에서 계정 등록 → 받은편지함이 내려받아지는가(한글 제목·첨부 포함)
2. 새 메일이 오면 알림이 뜨고 배지가 바뀌는가
3. 문서 화면 [메일 보내기] → PDF 첨부된 작성 창 → 실제 1통 발송 → 상대가 받는가, 보낸편지함에 남는가
4. 브라우저에서는 보내기가 막히고 안 읽은 수만 보이는가
5. 일부러 HTML 메일(원격 이미지 포함)을 열어 외부 요청이 막히는가
6. 비밀번호가 PC 밖(서버·로그)으로 나가지 않는가(서버 로그 확인)
