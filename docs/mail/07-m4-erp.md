# M4 — ERP 연동 (문서를 메일로 보내기 · 안 읽은 수 · 발송 이력)

> 2026-10-18 · **서버·DB 변경 있음** (새 표 `mail_logs` 1개, 마이그레이션 `0010_mail_logs`) · 새 라이브러리 없음
> 근거: [`02-implementation-plan.md`](./02-implementation-plan.md) M4, [`01-design.md`](./01-design.md)
> DB 승인: M4 진행 요청("M4 진행해줘")을 `mail_logs` 승인으로 보고 진행했다. **표 추가만** 하며 기존 표·데이터는 바꾸지 않는다. 개발 PC 의 DB 에만 적용했고 운영 서버에는 아직 적용하지 않았다.

## 만든 것
| 영역 | 내용 |
|---|---|
| **문서 → 메일 보내기** | 문서관리(견적서·거래명세서·세금계산서·발주서)의 **[발송] 버튼**: 데스크톱 앱이면 메일 창이 열리며 쓰기 화면이 **PDF 첨부 + 받는 사람(거래처 담당자 이메일) + 제목 + 본문 초안**으로 채워진다. 직원이 고친 뒤 [보내기]. 보내는 계정은 **그 직원의 메일 계정**(서버가 대신 보내지 않는다) |
| 브라우저에서는 | 서버·웹에서 보내지는 않는다. 예전처럼 PDF 를 내려받고 내 메일 프로그램(mailto)이 열리는 동작만 그대로 둔다(내 PC 의 메일 프로그램이 보내는 것이며 ERP 가 보내는 것이 아님) |
| 메일 계정이 없을 때 | "메일 계정이 등록되어 있지 않습니다. 메일 창에서 먼저 계정을 설정해 주세요." 안내 (앱이 거절) |
| **발송 이력** | 앱에서 보낸 **직후** 화면이 서버에 받는 사람·제목만 알린다(`POST /api/mail/sent`). 문서 상세에 **메일 발송 이력**(시각·보낸 직원·받는 사람·제목)이 보인다. 이력이 없으면 영역이 나타나지 않는다. **참고용**(직원이 보고한 값) — 증빙은 메일 서버의 보낸편지함 |
| **안 읽은 메일 수** | 앱은 이 PC 받은메일함의 안 읽은 수가 **바뀔 때와 5분마다** 서버에 숫자만 알린다(`PUT /api/mail/unread`, 서버 메모리, 본인 것만). 앱의 사이드바 [메일] 버튼에 숫자 표시. **브라우저 사이드바**에는 "안 읽은 메일 N통"만 보이고(2분마다 읽음, 클릭 불가 — 메일은 앱에서) 숫자가 없거나 30분 넘게 소식이 없으면 안 보인다 |

## 서버 API (`routers/mail.py`)
| 요청 | 설명 | 권한·검증 |
|---|---|---|
| `PUT /api/mail/unread` `{unread}` | 내 안 읽은 수 알리기 | 로그인. 0~99,999 정수만. 본인 키로만 저장 |
| `GET /api/mail/unread` | 내 안 읽은 수 | 본인 것만(**대표도 남의 것은 못 봄**). 30분 넘게 소식 없으면 `null` |
| `POST /api/mail/sent` | 문서 발송 이력 남기기 | 로그인 + **문서가 실제로 있어야 함**(없으면 404). 받는 사람 1~50명·주소 형식 검사(줄바꿈 등 거절), 제목 255자·제어 문자는 공백으로 |
| `GET /api/mail/logs?doc_type&doc_id` | 그 문서의 발송 이력 (최근 50건) | 로그인 + 문서 존재. **본문·첨부·메일 계정은 저장도 응답도 하지 않음** |

`mail_logs` 표: `id, created_at, sender_user_id(FK users, 삭제 시 SET NULL), doc_type, doc_id, to_addresses(1000자), subject(255자)`, 인덱스 `(doc_type, doc_id)`.
지금 이력을 남길 수 있는 문서 종류는 `project_document`(견적서·거래명세서·세금계산서·발주서)뿐이다.

## 앱 쪽 (보안)
- 문서 PDF 는 서버 화면이 앱에 **바이트로 넘기고**, 앱이 `%PDF-` 머리말·20MB·비어 있지 않음을 확인한 뒤 **임시 파일**로 만든다. 보낸 뒤(또는 버릴 때) 지운다. 화면이 파일 경로를 넘기는 길은 없다.
- 새 통로(`composeDocument`, `consumePendingCompose`, `unread`)는 모두 **서버 화면에서 온 요청만** 받고 인자 형식을 엄격히 검사한다(문서 종류·번호·제목 255자·본문 2만 자·받는 사람 2천 자·파일 이름 200자). 쓰기 초안은 메일 창이 한 번만 가져간다.
- 안 읽은 수는 메신저 배지와 별개로 서버에 **숫자만** 간다. 메일 제목·보낸 사람·본문은 서버로 가지 않는다.

## 미확인 (직접 확인 필요)
1. **실제 화면 확인 안 함**: 문서 상세/목록의 [발송] → 메일 창 → 보내기 → 문서 상세 이력까지의 전체 흐름은 자동 시험(가짜 서버·가짜 화면)으로만 확인했다. 실제 앱에서 눈으로 확인해 주세요.
2. 실제 다음스마트워크 계정으로 PDF 첨부 발송(받는 사람 메일함 도착).
3. 앱 사이드바·브라우저 사이드바의 안 읽은 메일 숫자 모양.

## 직접 확인 목록
1. 앱 로그인 → 승인된 견적서의 [발송] → 메일 창에 PDF 첨부·받는 사람·제목·본문이 채워지는가 → [보내기]
2. 같은 문서 상세를 열면 **메일 발송 이력**에 방금 건이 보이는가 (브라우저에서 같은 계정으로 봐도 보임)
3. 메일 계정을 지운 상태에서 [발송] → 안내가 나오는가
4. 앱에서 안 읽은 메일이 있을 때 브라우저로 같은 계정에 로그인 → 사이드바에 "안 읽은 메일 N통"
5. 브라우저에서 [발송] → 예전처럼 PDF 가 내려받아지고 내 메일 프로그램이 열리는가

## 알려진 한계 (M4)
- 발송 이력은 직원이 보고한 값이라 위조·누락 가능(앱 밖에서 보낸 메일이나 보고 실패는 기록되지 않음). 증빙은 메일 서버의 보낸편지함.
- 견적서 등 **문서관리의 문서**만 연결했다. 재직증명서(본인 서류)·품의서·입출금 영수증 등은 연결하지 않았다.
- 한 번에 PDF 1개 첨부(엑셀 등은 쓰기 화면의 [파일 첨부]로 직접 추가).
- 안 읽은 수는 앱이 켜져 있는 동안만 서버에 전달된다(30분 넘게 소식이 없으면 웹에서 사라짐).
- 메일 보내기 중 앱이 닫히거나 서버가 꺼져 있으면 이력이 남지 않을 수 있다(메일 자체는 나감).

## 운영 반영 순서 (아직 하지 않음)
1. 운영 DB 백업(`pg_dump`) 2. 코드 배포 3. `alembic upgrade head`(표 `mail_logs` 추가) 4. 프론트엔드 빌드 반영 5. 앱 설치 파일 재배포(`npm run dist` → `release` 폴더) — 앱이 새 통로(`composeDocument` 등)를 가져야 문서 [발송]이 메일 창을 연다. 예전 앱에서는 이 버튼이 이전처럼 mailto 로 동작한다.
