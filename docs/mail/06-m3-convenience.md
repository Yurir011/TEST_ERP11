## 만든 것
| 영역 | 내용 |
|---|---|
| **삭제** | 목록의 [삭제] 와 읽기 화면의 [삭제] 는 고른 메일을 **휴지통으로 옮긴다**(서버에서도, 되살릴 수 있다). 여러 통 가능. 휴지통 폴더를 찾지 못하면 **지우지 않고** 이유를 알린다(조용히 완전 삭제로 바뀌지 않는다) |
| **완전삭제** | 휴지통(또는 스팸메일함) 안에서는 버튼이 **[완전삭제]** 로 바뀌고, "되돌릴 수 없습니다" 확인을 받은 뒤에만 서버에서 지운다. 앱도 휴지통·스팸메일함에 있는 메일만 완전 삭제를 받아 준다(화면이 잘못 요청해도 받은메일함 메일은 지워지지 않는다) |
| **스팸신고** | 스팸메일함으로 옮긴다(스팸메일함 안에서는 비활성). 스팸메일함 폴더가 없으면 알리고 옮기지 않는다 |
| **이동** | [이동] 메뉴에서 폴더를 고르면 옮긴다(현재 폴더는 메뉴에서 빠진다). 옮긴 메일은 도착 폴더에도 바로 보인다 |
| **전달(도구줄)** | 목록에서 **한 통**만 고르면 [전달]이 켜져 그 메일의 전달 쓰기 화면이 열린다 |
| **본문 검색** | 검색칸의 **[본문 포함]** 을 켜고 검색하면 **서버가** 본문·제목·보낸 사람을 찾아, 이 PC 에 받아 둔 메일 중 해당하는 것만 목록에 남긴다("서버에서 본문까지 검색한 결과입니다" 표시). 서버 검색이 실패하면 제목·보낸 사람 검색으로 대신하고 이유를 알린다. [본문 포함]을 끄면 서버에 묻지 않고 제목·보낸 사람만 찾는다. 전체메일에서는 휴지통·스팸을 뺀 모든 폴더를 찾는다 |
| **새 메일 자동 확인** | 서버가 IDLE(새 메일을 먼저 알려 주는 기능)을 지원하지 않아서 앱이 **2분마다** 받은메일함을 서버와 맞춰 본다. 앱이 트레이에 내려가 있어도, 메일 창이 닫혀 있어도 계속한다. 확인에 실패하면(오프라인 등) 멈추지 않고 다음 시간에 다시 하며, 같은 실패는 로그에 한 번만 경고로 남긴다 |
| **새 메일 알림** | 새로 도착한 **안 읽은** 메일이 있으면 시스템 알림을 띄운다: 한 통이면 "보낸 사람 / 제목", 여러 통이면 "새 메일 N통" + 앞의 세 통 + "외 N통". **알림을 누르면 메일 창이 열리며 그 메일로 이동**한다(여러 통이면 메일 창만 연다). 이미 열려 있는 창이면 그 창을 앞으로 가져온다. 메일 창을 **보고 있는 중**에는 알림을 띄우지 않고 목록만 새로 읽는다 |
| 알림이 뜨지 않는 경우 | 처음 계정을 등록한 직후(받은메일함이 비어 있던 첫 동기화)의 예전 메일, 읽음 표시로 도착한 메일, 이미 알린 메일 |
| **자동 새로고침** | 확인 결과 목록이 바뀌면 열려 있는 메일 창이 **새로고침을 누르지 않아도** 목록을 다시 읽는다 |
| **배지** | 작업 표시줄 배지와 트레이 설명은 **메신저 안 읽은 수 + 메일 안 읽은 수의 합**(999 까지)이고, 설명에는 "안 읽은 메시지 2건 · 메일 3통"처럼 나뉘어 보인다. 메일을 열거나 읽음 표시·이동·삭제를 하면 바로 다시 계산한다(결정: 배지는 합쳐서 하나로) |
| 앱 시작 | 앱을 켜면 이전에 받아 둔 안 읽은 메일 수가 배지에 바로 반영된다 |

## 보안·안정성 장치
- 서버 화면에서 온 요청만 받는다(안내 화면·PDF 새 창은 거절). 메일 번호 목록은 1~500개의 양의 정수만, 폴더 이름은 제어 문자 없는 255자 이내만, 검색어는 200자 이내만 받는다.
- 이동·삭제는 **서버의 MOVE** 를 쓴다(복사 후 삭제가 아니라서 중간에 끊겨도 메일이 사라지지 않는다). 서버에서 옮긴 메일은 새 번호를 받으므로 원래 폴더의 로컬 사본은 지우고 도착 폴더는 곧바로 다시 읽는다.
- 같은 계정에 동시에 여러 번 접속하지 않도록 새 메일 확인·사용자 동작을 한 줄로 세워 처리한다. 확인이 아직 끝나지 않았으면 겹쳐 시작하지 않는다.
- 확인 간격 환경변수(`BENCH_MAIL_POLL_MS`)는 1초~1시간 범위로만 쓰고 이상한 값은 기본(2분)으로 돌린다(시험용).

## 미확인 (직접 확인 필요)
1. **실제 다음스마트워크**: 보낸·휴지통·스팸 폴더 이름과 "용도 표시"(서버가 알려 주지 않으면 이름 `휴지통`·`스팸메일함`·`Trash`·`Spam` 등으로 짐작한다), **서버 본문 검색이 한글 검색어를 지원하는지**(가짜 서버는 영문만 찾아 주어 한글 본문 검색은 실제 서버에서만 확인할 수 있다), 이동·삭제가 웹메일에서도 똑같이 보이는지.
2. **시스템 알림을 실제로 눌렀을 때** 메일 창이 열리고 그 메일로 이동하는지(알림 클릭 처리 로직은 시험했지만 Windows 알림 자체는 사람이 눌러 봐야 한다), 알림이 보이는 모양, **작업 표시줄 배지**의 합산 모양.
3. 2분마다 접속하는 것이 메일 서비스의 접속 제한에 걸리지 않는지(시간당 30회 정도). 문제가 되면 간격을 늘려야 한다.
4. 앱을 오래 켜 둔 상태에서의 안정성(절전 모드 복귀 후 첫 확인 등).

## 직접 확인 목록
1. 다른 곳(웹메일 등)에서 내게 메일을 보내 보세요 → 최대 2분 안에 **알림**이 뜨는가 → 알림을 누르면 메일 창이 열리며 그 메일이 열리는가
2. 메일 창을 열어 둔 채로 새 메일을 받으면 **새로고침 없이** 목록에 생기는가, 작업 표시줄 배지에 숫자가 붙는가(메신저 안 읽은 수와 합산)
3. 메일을 골라 [삭제] → 휴지통에 보이는가(웹메일 휴지통에서도) → 휴지통에서 [완전삭제] → 확인 창
4. [스팸신고], [이동] > 폴더 선택, 한 통만 골라 [전달]
5. 검색 [본문 포함] 으로 **본문에만 있는 한글 단어**를 찾아 보기(찾아지지 않으면 알려 주세요)
6. 폴더 이름이 이상하게 보이거나 삭제가 "휴지통 폴더를 찾을 수 없다"고 나오면 실제 폴더 이름을 알려 주세요

## 알려진 한계 (M3)
- 새 메일 자동 확인은 **받은메일함만** 한다(다른 폴더는 열 때·새로고침 때 맞춘다).
- 휴지통 비우기·삭제 취소(되돌리기) 버튼, 폴더 만들기·이름 바꾸기, 초안 저장은 없다.
- 스팸신고는 메일을 스팸메일함으로 옮길 뿐, 서버의 스팸 필터를 학습시키지는 않는다.
- 서버 본문 검색은 서버가 지원하는 검색만큼만 된다(한글 지원 여부는 서버에 따라 다르다). 이 PC 에 받아 두지 않은(90일 이전) 메일은 번호가 없어 목록에 나오지 않는다.
- 알림은 앱이 켜져 있는 동안만 뜬다(앱을 완전히 종료하면 확인도 멈춘다. 트레이에 내려가 있는 것은 켜져 있는 상태).
