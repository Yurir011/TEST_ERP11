# 메일 기능 구현 계획

> 2026-10-17 · 근거: [`01-design.md`](./01-design.md)(설계서) · 상태: **구현 전**
> 각 단계가 끝나면 체크박스를 `[x]` 로 하고 `(완료: YYYY-MM-DD)` 를 남긴다. 단계마다 결과 문서 `docs/mail/0N-…md` 를 만든다.

## 1. 최종 결정 사항

| # | 결정 |
|---|---|
| 1 | 메일은 **데스크톱 앱에서만** 사용 (썬더버드형 로컬 클라이언트). 앱이 IMAP(993/SSL)·SMTP(465/SSL)에 직접 접속하고 메일을 **그 PC 에 보관** |
| 2 | 웹(브라우저)에는 **안 읽은 메일 수만** 표시. 앱이 숫자만 서버에 보고 (제목·발신자·본문은 서버로 보내지 않음) |
| 3 | 문서 발송(견적서 등)은 **해당 직원의 계정**으로 앱에서 발송. 공용 계정·서버 발송 없음 |
| 4 | **웹에서는 발송 불가.** 브라우저의 [메일 보내기]는 비활성 + "데스크톱 앱에서 사용" 안내 |
| 5 | 서버는 메일 비밀번호·본문·첨부를 **보관하지 않음.** 비밀번호는 PC 의 `safeStorage` 에만 |
| 6 | 메일 서비스: 다음 스마트워크 (서버 주소·인증 방식은 M0 에서 확정) |

## 2. 아직 정해지지 않은 것 (해당 단계 시작 전에 확인)

| 항목 | 필요한 단계 | 담당 |
|---|---|---|
| ~~IMAP/SMTP 서버 주소, 인증 방식~~ → `imap.daum.net:993`, `smtp.daum.net:465`, 비밀번호 방식으로 확정 (실제 로그인·폴더 이름은 M1 에서 확인) | M0 | 완료 |
| `mail_logs` 표 신설(리비전 0010) 승인 | M4 | **사용자 승인 필수** (DB 변경) |
| 안 읽은 수 보관: 서버 메모리(권장) vs 표 | M4 | 권장안으로 진행, 영속 필요 시 승인 |
| 메일 배지를 메신저 배지와 합산할지 | M3 | 구현 전 확인 |
| 동기화 기본 범위(권장: 최근 90일) | M1 | 권장안으로 진행 |

## 3. 지킬 규칙

- DB 변경·데이터 삭제는 사전 승인 없이 하지 않는다. 실제 운영 데이터에 영향 주는 작업은 하지 않는다.
- 비밀번호·토큰을 로그·화면·문서·채팅에 남기지 않는다. 메일 비밀번호는 사용자가 앱 화면에서만 입력한다.
- 자동 테스트는 **가짜 IMAP/SMTP 서버**만 사용한다. 실제 서버 접속·발송 확인은 사용자가 직접 한다. 실행하지 않은 검증을 했다고 쓰지 않는다.
- 새 기능과 리팩토링을 섞지 않는다. 문서 PDF 는 **기존 다운로드 엔드포인트**를 재사용한다.
- 모든 새 코드에 `[Mail] ...` 접두사 디버그 로그. 로그에 비밀번호·본문 금지.
- 커밋마다 버전 번호를 묻고 `[V.x.xx.xxx]` 접두사를 붙인다. DB 표가 추가되는 M4 는 부 자리 상향(V.0.71.001) 권장.

## 4. 단계별 계획

### M0. 사전 검증 (PoC) — 코드는 `desktop/scripts/` 안에서만, 제품 코드 변경 없음
- [x] 네이티브 SQLite(`better-sqlite3` 등)가 Electron 44 + electron-builder(`npmRebuild:false`, `asarUnpack`) 설치 파일에서 로드되는지 확인. 실패 시 대안(파일 기반 저장소 / `node:sqlite`) 결정
- [x] `imapflow`·`mailparser`·`nodemailer` 가 Electron 메인 프로세스에서 동작하는지 가짜 서버로 확인
- [x] 다음 스마트워크 접속 방식 확인: `imap.daum.net:993`/`smtp.daum.net:465`(SSL), 비밀번호 인증(`AUTH=PLAIN`), OAuth 없음 — 서버 기능 조회로 확인(2026-10-18). 실제 로그인·폴더 이름·2단계 인증/앱 비밀번호 여부는 M1 연결 테스트에서 사용자 확인
- [x] `safeStorage` 사용 가능 여부 확인(암호화 불가 시 저장 거부 정책 검증)
- 산출: [`03-m0-poc.md`](./03-m0-poc.md) (결정: 저장소 `better-sqlite3`, 라이브러리 확정) — 2026-10-18 기술 검증·서버 기능 확인 완료
- 완료 기준: 결정이 문서에 기록되고, 설치 파일에서 저장소·IMAP 모듈이 로드됨

### M1. 읽기 (서버·DB 변경 없음)
- [x] `src/mail/account.ts` — 계정 설정·연결 테스트, 비밀번호 `safeStorage` 저장, 저장소 없으면 거부
- [x] `src/mail/store.ts` — 로컬 저장소(헤더·본문·첨부 메타·읽음·폴더), 스키마 버전
- [x] `src/mail/sync.ts` — 폴더 목록, UID 증분 동기화, 연결 끊김 복구, 기본 최근 90일
- [x] `src/mail/html.ts` — HTML 메일 정리·격리 표시(스크립트 차단, 원격 이미지 기본 차단 + "이미지 보기", 링크는 확인 후 기본 브라우저)
- [x] IPC(`preload.ts`/`main.ts`): `mail.*` 읽기 API, 발신자 출처 검사, 비밀번호는 렌더러로 전달 금지
- [x] 화면: 계정 등록 화면, 폴더 | 목록 | 본문 3단, 첨부 저장/열기(실행 파일 확장자 경고), 읽음 표시. 앱에서만 메뉴 표시
- [x] 테스트: 파서(한글 인코딩·첨부)·동기화(증분/재연결)·저장소·HTML 정리(스크립트/원격 리소스 차단, 변형 확인)·IPC 검증, 가짜 IMAP 으로 앱 smoke
- 산출: [`04-m1-read.md`](./04-m1-read.md) (2026-10-18 구현·자동 검증 완료, 실제 계정 로그인은 사용자 확인 대기)
- 완료 기준: 가짜 서버로 자동 테스트 통과 ✔ + 사용자가 실제 계정을 등록해 받은편지함이 보임(**사용자 확인 대기**)

### M2. 쓰기·보내기 (서버·DB 변경 없음)
- [x] `src/mail/send.ts` — 새 메일·답장·전달, 첨부, 주소 형식 검증, 줄바꿈 헤더 인젝션 방지, 첨부 크기 제한
- [x] 보낸편지함 저장(IMAP APPEND), 전송 실패 시 임시보관·재시도 안내
- [x] 화면: 작성 창(받는사람/참조/제목/본문/첨부), 답장·전달 버튼
- [x] 테스트: 가짜 SMTP 로 정상/실패/인젝션 거부/크기 초과
- 산출: [`05-m2-send.md`](./05-m2-send.md) (2026-10-18 구현·자동 검증 완료, 실제 계정 발송은 사용자 확인 대기)
- 완료 기준: 자동 테스트 통과 ✔ + 사용자가 실제로 1통 보내 수신 확인(**사용자 확인 대기**)

### M3. 편의 기능 (서버·DB 변경 없음)
- [ ] 검색(제목·발신자·본문), 삭제/휴지통, 폴더 이동 — **제목·보낸 사람 검색과 읽음 표시·별표는 M1 화면 개편에서 먼저 구현**(본문 검색·삭제·이동은 남음)
- [ ] 새 메일 감지 — **서버가 IDLE 을 지원하지 않으므로 주기적 확인(폴링)** → 시스템 알림 → 알림 클릭 시 해당 메일로 이동(메신저 알림과 같은 방식)
- [ ] 작업 표시줄/트레이 배지 정책 결정 후 반영
- [ ] 테스트: 폴링 신규 메일 감지·재연결, 알림 이동 규칙, 검색
- 산출: `docs/mail/06-m3-convenience.md`

### M4. ERP 연동 (서버 변경 — `mail_logs` 승인 후)
**서버**
- [ ] (승인 후) 리비전 `0010_mail_logs` + 모델: id, created_at, sender_user_id(FK, SET NULL), doc_type, doc_id, to_addresses, subject. 인덱스 `(doc_type, doc_id)`. 본문·첨부 저장 금지
- [ ] `routers/mail.py`: `PUT/GET /api/mail/unread`(본인 것만, 서버 메모리), `POST /api/mail/sent`(문서 열람 권한 확인), `GET /api/mail/logs`
- [ ] 테스트: 본인 외 접근 불가(대표도), 권한 없는 문서 기록 거부, 입력 검증, 비밀 값 비노출
**앱·화면**
- [ ] 앱: 안 읽은 수를 변할 때와 몇 분마다 서버에 보고, 보낸 직후 발송 이력 보고
- [ ] 문서 화면(견적서·거래명세서·세금계산서·증명서) [메일 보내기]: 앱이면 작성 창을 열고 기존 PDF 엔드포인트로 받은 PDF 를 첨부, 거래처·담당자 이메일을 받는 사람 후보로 채움. 브라우저면 비활성 + 안내
- [ ] 웹 사이드바/대시보드에 안 읽은 메일 수 표시
- [ ] 문서 상세에 발송 이력 표시
- [ ] 테스트: 앱/브라우저 분기, 안 읽은 수 표시, 버튼 상태
- 산출: `docs/mail/07-m4-erp.md`, 사용 설명서 "메일" 절, CHANGELOG, README 갱신, 버전 상향(권장 V.0.71.001)
- 운영 반영: **DB 백업(`pg_dump`) → 코드 배포 → `alembic upgrade head`**, 앱 설치 파일 재배포

## 5. 단계별 검증 원칙
1. 각 단계 끝에 backend `pytest`, frontend `npm test`·`npm run build`, desktop `npm test` 전체 통과(해당 영역).
2. 핵심 규칙(비밀번호 비노출, HTML 격리, 본인 외 접근 불가)은 규칙을 일부러 깨뜨려 테스트가 실패하는지 확인(변형 확인).
3. 앱 smoke: 개발 실행 + 설치 파일 두 방식.
4. 사용자가 직접 확인할 항목은 단계 문서의 "직접 확인 목록"에 남기고, 확인하지 못한 것은 "미확인"으로 표시.

## 6. 위험과 대응
| 위험 | 대응 |
|---|---|
| ~~스마트워크가 OAuth 전용~~ | 해소: 비밀번호 방식(`AUTH=PLAIN`) 확인. 2단계 인증 계정은 앱 비밀번호 안내 필요(M1) |
| 서버가 IDLE 미지원 | 새 메일은 폴링으로 감지(M3), 간격은 설정값 |
| 네이티브 모듈이 설치 파일에서 실패 | M0 에서 확인, 순수 JS 저장소로 대체 |
| HTML 메일 악성 내용 | 격리 표시·외부 리소스 차단·변형 테스트 |
| 대용량 사서함 | 기간 제한, 증분 동기화, 첨부는 필요 시 내려받기 |
| 분실·퇴사 PC 의 로컬 메일 | 서버에서 막을 수 없음 → 메일 비밀번호 변경·디스크 암호화 안내(한계로 문서화) |
| 발송 이력 위조 가능 | 참고용으로 명시. 증빙은 메일 서버의 보낸편지함 |

## 7. 진행 순서 요약
```
M0 PoC(결정) → M1 읽기 → M2 보내기 → M3 편의 → M4 ERP 연동(DB 승인 후)
                  └ 서버·DB 변경 없음 ┘          └ 서버 배포 필요 ┘
```
M0 이 끝나기 전에는 M1 을 시작하지 않는다.
