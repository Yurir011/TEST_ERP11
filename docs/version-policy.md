# 버전 관리 규칙

> 2026-10-17 시작 · 현재 버전 **V.0.07.150** (최초 기준)

## 표기
| | 형식 | 예 | 어디에 쓰나 |
|---|---|---|---|
| 화면 표기 | `V.주.부(2자리).빌드(3자리)` | `V.0.07.150` | 화면(사이드바 아래), 앱 트레이·안내 화면, 설치 파일 이름, 커밋 메시지, 변경 이력 |
| 내부 표기 | `주.부.빌드` (0 을 붙이지 않음) | `0.7.150` | `desktop/package.json`, `frontend/package.json`, `backend/app/version.py` |

내부 표기를 따로 두는 이유: npm·설치 파일 도구가 `07` 처럼 0 으로 시작하는 숫자를 버전으로 인정하지 않기 때문이다. 두 표기는 항상 같은 값이고, 프로그램이 알아서 바꿔 준다(`V.0.07.150` ↔ `0.7.150`).

## 어디에 보이나
- 웹 화면·앱 모두: 왼쪽 사이드바 맨 아래 `V.0.07.150`(서버 버전). 앱이 서버와 다른 버전이면 `V.0.07.150 · 앱 V.0.07.149` 처럼 앱 버전도 함께 표시(문의할 때 확인용).
- 서버: `GET /api/health` 응답의 `version`.
- 데스크톱 앱: 트레이 아이콘 우클릭 메뉴 맨 위, 마우스를 올렸을 때의 툴팁, 첫 안내 화면.
- 설치 파일: `BENCH-ERP_V.0.07.150_Setup.exe`.

## 번호를 올리는 기준 (권장)
| 올리는 자리 | 언제 | 예 |
|---|---|---|
| 빌드(마지막 3자리) | 버그 수정, 작은 개선 — 화면·DB 구조 변화 없음 | V.0.07.150 → V.0.07.151 |
| 부(가운데 2자리) | 새 기능 추가, DB 표 추가 등 **배포할 때 DB 갱신이 필요한 변경** | V.0.07.151 → V.0.08.001 (빌드는 001 로 돌아간다) |
| 주(맨 앞) | 구조가 크게 바뀌거나 정식 오픈 같은 큰 구분 | V.0.08.012 → V.1.00.000 |

번호는 사람이 정한다. 커밋할 때마다 번호를 물어보고(아래), 새 버전으로 올리기로 하면 다음 절차를 따른다.

## 버전을 올리는 절차
1. **번호 올리기** — 세 곳(앱, 웹 화면, 서버)을 한 번에 바꾼다.
   ```
   cd desktop
   npx tsx scripts/bump-version.ts V.0.07.151        # 낮추거나 같은 번호는 --force 가 있어야 한다
   ```
   한 곳이라도 빠지면 `backend/tests/test_version.py` 가 실패하므로 잊어도 테스트가 알려 준다.
2. **변경 이력 적기** — 루트 `CHANGELOG.md` 맨 위에 새 버전 항목(바뀐 내용)을 쓴다.
3. **테스트** — backend `pytest`, frontend `npm test`·`npm run build`, desktop `npm test`.
4. **커밋** — 메시지 앞에 버전 접두사: `[V.0.07.151] fix(messenger): 설명`.
5. **설치 파일 만들기** — `cd desktop && npm run dist` → `desktop/release/BENCH-ERP_Setup_0.7.151.exe`
   (기본 서버 주소 `http://www.epik.bio:3102` 가 자동으로 들어간다. 다른 서버용은 `set BENCH_DEFAULT_SERVER=http://주소 && npm run dist`)
6. **직원에게 알리기** — `npm run publish-release -- --notes "바뀐 내용"` → 서버가 최신 버전으로 안내하고, 직원 앱 화면 위쪽에 "새 버전이 있습니다 [다운로드]"가 뜬다.
7. **운영 서버에 올리기** — 코드를 서버에 배포하기 전에 **DB 백업(`pg_dump`)**, DB 구조가 바뀐 버전이면 `alembic upgrade head`. (README "DB 구조 변경", "백업과 복원")

## 커밋 규칙
- 커밋할 때마다 **버전 번호를 먼저 묻고**, 메시지 맨 앞에 `[V.0.07.150]` 를 붙인다. (CLAUDE.md "커밋 규칙 — 버전 번호"에도 적혀 있다.)
- 형식: `[V.0.07.150] type(scope): 설명` — type 은 feat, fix, docs, test, refactor 등.
- 이 규칙을 정하기 전의 커밋(V.0.07.150 이전)에는 접두사가 없다.

## 이전 버전으로 되돌리기
- 서버에는 올린 설치 파일이 `backend/storage/client_releases/` 에 버전별로 남는다(이전 파일은 지우지 않는다). 직원 PC 를 되돌리려면 이전 버전 설치 파일을 직접 실행하면 된다.
- 서버 코드를 되돌릴 때 DB 구조가 바뀐 버전이었다면, 먼저 DB 를 백업해 둔 파일로 복원하거나 `alembic downgrade` 를 쓴다(데이터가 있는 표를 지우므로 신중하게, README "DB 구조 변경").
