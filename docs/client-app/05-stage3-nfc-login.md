# 3단계 — NFC 카드 로그인

> 2026-10-17 · 승인: 로그인 방식 추가(카드 + 승인된 PC) · 새 DB 표 없음 · 새 패키지 `cryptography==50.0.1`(서명 확인)

## 동작

```
카드를 리더에 댐 → 앱(main)이 카드 번호를 읽음
  → 서버에서 1회용 확인값(nonce) 받음            POST /api/auth/nfc/challenge   (승인된 기기만)
  → (nonce, 카드 번호)에 이 PC 의 비밀키로 서명
  → 서버에 로그인 요청                            POST /api/auth/nfc/login
  → 서버가 확인 후 토큰 발급 → 화면은 토큰만 받아 로그인
```

서버가 확인하는 것: ① 승인된 기기 ② nonce 가 이 기기에 발급된 유효한(60초, 1회용) 값 ③ 서명이 맞는지(카드 번호에 묶여 있음) ④ 사용 중인 카드 ⑤ 활성 직원. 하나라도 틀리면 거부한다.

- **카드 번호만으로는 로그인할 수 없다.** 카드 번호는 복제할 수 있지만, 승인된 PC 의 비밀키 서명이 없으면 통하지 않는다. 같은 요청을 가로채 다시 보내도(nonce 1회용) 통하지 않는다.
- 비밀키와 서명, (로그인 중의) 카드 번호는 화면(웹)에 전달되지 않는다. 화면은 결과(토큰 또는 안내 문구)만 받는다.
- 실패가 반복되면(기본 5회/10분) 그 기기를 5분 잠근다(비밀번호 로그인과 같은 규칙, 따로 센다). 만료된 nonce 는 실패로 세지 않는다.
- 카드 로그인 토큰은 **8시간**(`NFC_TOKEN_EXPIRE_MINUTES`)이고, 카드·기기 번호를 담고 있어 **카드를 중지·삭제하거나 기기를 중지하면 이미 받은 토큰도 바로 거부**된다(요청마다 확인, 카드 로그인 토큰에만 추가 조회 2번).
- 변경 이력: `nfc_login_success / failed / blocked`. 카드 번호는 끝 4자리만 남는다.

## 앱이 카드를 쓰는 방식 (모드)
화면이 IPC 로 앱에 "카드가 닿으면 무엇을 할지" 알린다. 새로 불러온 화면은 항상 `off` 에서 시작한다.

| 모드 | 누가 | 카드가 닿으면 |
|---|---|---|
| `login` | 로그인 화면 | 앱이 서버에 로그인 요청, 화면에는 결과만 |
| `capture` | 직원 수정 화면의 [카드 읽기] | 카드 번호를 화면에 전달(등록용), 로그인은 하지 않음 |
| `off` | 그 외 모든 화면 | 아무 일도 없음 |

두 요청이 겹치면 `capture` > `login` 순(카드 등록 중에 로그인이 일어나지 않는다).

### 계획서와 달라진 점
- 계획서(§3.1)는 "로그인한 상태에서 다른 사람 카드가 닿으면 확인 창 후 전환"이었으나, **로그인한 상태에서는 카드를 받지 않는다.** 전환하려면 로그아웃한 뒤 카드를 댄다. 이유: 확인하기 전에 서버가 다른 사람의 로그인 성공을 기록해 버리고, 실수로 카드가 닿았을 때 계정이 바뀔 위험이 있다. 필요하면 확인 방식으로 다시 검토한다.

## 직접 확인 목록
1. 앱에서 **로그아웃** → 로그인 화면 아래 "카드로 로그인 — 등록된 카드를 리더에 대면 바로 로그인됩니다" 표시
2. 정혜란에게 등록한 카드(515D)를 대면 → 바로 로그인되고 첫 화면으로 이동, 이름이 정혜란인지
3. 등록하지 않은 카드를 대면 → "등록되지 않았거나 사용할 수 없는 카드입니다"
4. 직원 수정 화면에서 해당 카드를 **사용 중지** → 다시 로그아웃 후 카드를 대면 거부되는가, 이미 로그인한 다른 창은 다음 동작에서 로그인 화면으로 돌아가는가
5. 변경 이력에서 카드 로그인 성공·실패 기록, 카드 번호는 끝 4자리만
6. 브라우저(`http://localhost:5173`)의 로그인 화면에는 카드 칸이 없다

## 운영 서버(Docker) 배포 전
- 백엔드 이미지에 `cryptography`가 들어가야 한다(`requirements.txt`에 반영됨, `pip install -r requirements.txt`). 네이티브 확장 패키지라 이미지 빌드 환경(리눅스)에서 설치되는지 한 번 확인한다.
- `http` 로 서비스 중이면 토큰이 암호화 없이 오간다. 카드 로그인은 서명으로 재전송은 막지만 **https 적용을 권한다**.
