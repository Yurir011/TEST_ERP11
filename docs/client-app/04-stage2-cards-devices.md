# 2단계 — 기기·카드 등록

> 2026-10-17 · 승인: DB 표 추가(리비전 0007) · 코드: `backend/`, `frontend/`, `desktop/`

## 만든 것

### DB (Alembic `0007_nfc_cards_devices`) — 새 표 2개만 추가, 기존 표는 바꾸지 않음
| 표 | 내용 |
|---|---|
| `nfc_cards` | 직원(`user_id`, 직원이 삭제되면 함께 삭제) · `uid_hmac`(**카드 번호 원문이 아니라 HMAC 값**, 유일) · `uid_last4`(표시용) · 이름 · 사용 여부 · 등록자·등록일·마지막 사용일·중지일 |
| `client_devices` | 이름 · `public_key`(Ed25519 공개키 64자, 유일) · 상태(pending/approved/revoked) · 승인자·승인일 · 마지막 접속 시각·IP |

개발 DB 적용: 백업(`erp_db_20261017_102216_before_nfc_tables.dump`) 후 0006 → 0007, 새 표 0행, 기존 직원 8명 그대로. 테스트 DB 에서 내렸다 올리기(downgrade/upgrade)로 되돌리기도 확인.

### 서버 API
| API | 권한 | 비고 |
|---|---|---|
| `GET/POST /api/users/{id}/nfc-cards` | 대표·사이트 관리자 | 직원 관리와 같은 권한. 한 직원 5장까지. 번호 중복이면 409(누구 카드인지 알려 줌) |
| `PUT …/{card_id}/deactivate`, `DELETE …/{card_id}` | 대표·사이트 관리자 | 사용 중지한 카드도 번호는 남아 다른 직원에게 바로 등록되지 않음. 삭제하면 다시 등록 가능 |
| `POST /api/devices/register` | **로그인 없음**(앱) | 처음이면 승인 대기로 등록, 이미 있으면 현재 상태만 돌려줌. 승인 대기가 20개면 429 |
| `GET /api/devices`, `PUT …/approve`, `…/revoke`, `PUT …/{id}`(이름), `DELETE …/{id}`(대기 거절) | **대표만** | 사이트 관리자도 불가 |

- 카드 번호 원문은 응답·로그·감사 기록 어디에도 나오지 않는다(끝 4자리만).
- 변경 이력(감사 로그)에 `nfc_card_registered/deactivated/deleted`, `device_registered/approved/revoked/deleted`가 남는다.
- 설정 `NFC_UID_SECRET`(.env): 비워 두면 JWT 비밀키에서 파생. **한 번 정하면 바꾸지 않는다**(바꾸면 등록한 카드를 알아볼 수 없음).

### 화면 (웹)
- 직원 수정 화면 아래 **NFC 카드** 칸: 목록(이름·끝 4자리·마지막 사용), 사용 중지, 삭제.
  - 데스크톱 앱: [카드 읽기] → 카드를 대면 끝 4자리만 보여 주고 이름을 붙여 등록. 리더가 연결되기 전에는 버튼이 꺼져 있음.
  - 브라우저: 카드 번호를 직접 입력(16진수 검사).
- **설정 > 기기 관리**(대표만, 직원 계정 관리 화면의 버튼): 승인 대기를 맨 위에, 승인·거절·사용 중지·이름 변경.
- 변경 이력 화면: 새 이벤트 이름표와 "카드·기기" 필터.

### 데스크톱 앱
- 처음 실행하면 Ed25519 키를 만들고 **비밀키는 운영체제 보안 저장소(Windows DPAPI 등, Electron safeStorage)로 암호화**해 저장(`device-key.json`). 서버에는 공개키와 PC 이름만 보낸다. 비밀키·서명은 화면(웹)에 넘기지 않는다.
- 서버에 연결되면 자동으로 등록 요청을 보내고, 승인되기 전에는 1분마다 상태를 확인한다. 화면에서는 `benchClient.device.state()`로 읽을 수 있다.
- 키 파일이 깨지거나 바꿔치기되면 새 키를 만든다(그 PC 는 다시 승인받아야 함).

## 직접 확인 목록
1. (개발 PC) 서버를 새로 켜고(`start.bat` — 시작할 때 `alembic upgrade head` 실행) 대표 계정으로 로그인
2. 데스크톱 앱 실행(`npm.cmd start`) → 설정 > **기기 관리**에 "승인 대기"로 나타나는가 → 승인
3. 직원 수정 화면 > NFC 카드 > **카드 읽기** → 리더에 카드 → 끝 4자리 확인 → 등록. 같은 카드를 다른 직원에게 등록하면 거부되는가
4. 브라우저(앱이 아닌 곳)로 같은 화면을 열면 번호 직접 입력 칸이 나오는가
5. 변경 이력에 기기·카드 기록이 남는가

## 운영 서버(Docker) 배포 전
- 새 버전에는 리비전 0007 이 있다. **운영 DB 는 먼저 `pg_dump` 백업**을 하고 `alembic upgrade head`를 실행한다(README "DB 구조 변경").
- `NFC_UID_SECRET`은 선택(비우면 JWT 비밀키에서 파생). 정하려면 카드를 등록하기 **전에** 정한다.
- 이 단계에서는 카드로 로그인되지 않는다(3단계).
