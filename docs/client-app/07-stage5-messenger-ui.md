# 5단계 — 메신저 화면

> 2026-10-17 · 새 DB 표·패키지 없음 · 서버는 4단계([06-stage4-messenger-server.md](./06-stage4-messenger-server.md)) · 코드: `frontend/src/features/messenger/`, `frontend/src/lib/realtime.ts`

## 화면 구성
- 사이드바에 **메신저** 메뉴(일반 직원·대표·사이트 관리자 모두)와 안 읽은 수 배지. 주소는 `/messenger`, `/messenger/{대화방}`.
- 왼쪽 **대화방 목록**(최근 대화 순, 마지막 글·시각·안 읽은 수, 그룹·알림 끔 표시, [새 대화]), 오른쪽 **대화 화면**.
- **대화 화면**: 날짜 줄, 같은 사람이 5분 안에 이어 보낸 글은 묶음(이름·시각은 묶음 처음/마지막에만), 내 글은 오른쪽 파란색. 위로 올라가 [이전 메시지 더 보기](50개씩, 보던 자리 유지).
- **보내기**: Enter 보내기, Shift+Enter 줄바꿈, **한글 조합 중 Enter 는 보내지 않음**. 보내면 "보내는 중"으로 먼저 보이고, 실패하면 이유와 [다시 보내기]·[삭제](다시 보내도 서버에 두 번 저장되지 않음).
- **파일**: 클립 버튼으로 첨부(20MB, 서버가 파일 내용으로 형식 확인). 이미지는 그림으로, PDF 는 새 창으로 열기, 그 외 문서는 다운로드. 
- **글 표시**: 줄바꿈 유지, `http(s)` 주소만 링크(새 창·opener 차단), **글 안의 HTML 은 요소가 아니라 글자 그대로** 보임.
- **읽음 표시(카카오톡 방식)**: 메시지마다 **아직 읽지 않은 사람 수**를 숫자로 붙이고, 모두 읽으면 숫자가 사라진다. 1:1 은 상대가 읽기 전까지 `1`, 그룹은 읽지 않은 사람 수(`3` → `2` → `1` → 없음)가 실시간으로 줄어든다. 내 메시지와 남의 메시지 모두에 붙는다(남의 메시지는 나 자신이 아직 안 읽었으면 포함). 보낸 사람은 세지 않고, 나간 사람은 세지 않으며, 나중에 들어온 참여자는 들어오기 전 메시지의 숫자에 들어가지 않는다. 대화 화면을 **보고 있는 동안에만** 읽은 것으로 처리한다(창이 가려졌거나 다른 창에 초점이 있으면 처리하지 않고, 다시 보면 처리).
- **그룹 대화**: 참여자 추가, 나가기(확인 후). 모든 대화: 알림 끄기.
- 실시간 연결이 끊기면 대화 화면 위에 안내가 뜨고(보내기는 계속 가능), 다시 연결되면 **그 사이 놓친 메시지를 번호 기준으로 받아 합친다**.

## 알림
- 새 메시지가 오면(내가 보낸 것·알림 끈 대화방·**지금 보고 있는 대화방**은 제외): 데스크톱 앱이면 시스템 알림(`그룹명 · 보낸 사람` / 내용 또는 `[파일] 이름`), 같은 메시지가 두 번 와도 한 번만.
- 앱 아이콘 배지(mac/Linux)·트레이 툴팁·**창 제목 `(3) BENCH ERP`** 에 전체 안 읽은 수. 브라우저에서도 창 제목은 바뀐다.
- 알림을 눌러도 지금은 창만 앞으로 나온다(해당 대화방으로 바로 가기는 하지 않음 — 아래 남은 것).

## 구조
- `lib/realtime.ts`: 연결 하나를 앱 전체가 공유. 자동 재연결(1→2→5→10초, 로그인 오류(4401)는 60초), 30초 ping 과 응답 확인, 재연결할 때마다 `epoch` 증가, 토큰은 연결 때마다 최신 값.
- `MessengerContext.tsx`: 로그인한 동안 연결·대화방 목록·안 읽은 수·알림·배지를 관리. 로그아웃하면 연결을 닫고 목록을 지움.
- `messengerState.ts`: 목록 갱신·읽음 반영·메시지 합치기·묶음 계산·표시 글자 등 순수 함수(테스트 대상).
- `<form>` 을 쓰지 않는 입력칸(앱 전체의 "Enter = 다음 칸 이동" 규칙과 충돌 방지).
- 사이드바 메뉴는 누를 때마다 페이지를 새로 불러오는 기존 방식이라, 메뉴를 옮길 때마다 연결이 새로 맺어진다(놓친 메시지는 위 복구로 받음).

## 직접 확인 목록
`start.bat` 으로 서버를 켜고 `desktop` 에서 `npm.cmd run start:local` (앱), 브라우저 `http://localhost:5173` 에 다른 직원으로 로그인해 두 사람이 대화합니다.
1. 사이드바 **메신저** → [새 대화] → 직원을 고르면 1:1, 두 명 이상이면 그룹 이름을 묻는가
2. 메시지를 보내면 상대 화면(앱·브라우저)에 바로 나타나는가, 상대가 다른 메뉴에 있어도 사이드바 배지가 뜨는가
3. 앱을 **최소화·다른 창을 본 상태**에서 메시지가 오면 시스템 알림이 뜨는가, 알림을 누르면 창이 나오는가
4. Enter 보내기·Shift+Enter 줄바꿈, 한글을 입력하는 도중 Enter 를 눌렀을 때 마지막 글자가 중복되지 않는가
5. 이미지·PDF·엑셀 파일을 보내고 받는 쪽에서 이미지는 그림으로, PDF 는 새 창으로, 엑셀은 다운로드되는가. 20MB 넘는 파일은 안내가 뜨는가
6. 내 메시지 옆의 숫자(아직 안 읽은 사람 수)가 상대가 읽으면 줄어들다가 사라지는가, 그룹에서도 읽는 사람이 늘수록 줄어드는가
7. 그룹: 참여자 추가·나가기, 나간 뒤에는 그 대화가 목록에서 사라지는가
8. 서버를 껐다 켜면(또는 네트워크를 잠시 끊으면) 안내가 뜨고, 다시 연결되면 그 사이 메시지가 채워지는가
9. 대표 계정으로 로그인해도 **다른 사람들의 대화는 보이지 않는가** (변경 이력에도 대화 내용이 없는가)

## 읽음 숫자로 변경 (2026-10-17)

- 검증: 프론트엔드 단위 테스트(계산 규칙, 말풍선, 읽는 사람이 늘 때 숫자가 줄어드는 화면) + 규칙을 망가뜨리면 실패하는 것 확인 + **실제 브라우저 세 창(그룹)에서 7/7**: A 가 보내면 `2` → B 가 읽으면 `1` → C 가 읽으면 사라짐 / 남이 보낸 메시지에도 숫자 / 내가 창을 보면 그 숫자도 사라짐 / 나중에 들어온 사람은 이전 메시지에 포함되지 않음.
