## 0. 원칙

1. 기능·API 계약·DB 호환성을 바꾸지 않는다. 사용자에게 보이는 동작이 바뀌는 항목은 **[승인 필요]** 로 표시하고 따로 묻는다.
2. **테스트로 현재 동작을 먼저 고정한 뒤** 구조를 바꾼다. 테스트가 없는 영역은 손대지 않는다.
3. 단계마다 독립 커밋 + 검증(`tsc`, `oxlint`, `npm run build`, 백엔드 테스트) 결과를 보고한다.
4. 운영 데이터와 DB 스키마는 건드리지 않는다. 테스트는 별도 `erp_test` DB에서만 실행한다.
5. 리팩토링과 신규 기능을 섞지 않는다. 버그가 발견되면 별도 커밋으로 분리하고 먼저 보고한다.

## 2. 단계별 상세

### P0. 안전망 구축 (분석 A4, 테스트 부재)

**할 일**
- 백엔드: `pytest` 도입(개발 전용 의존성), 별도 `erp_test` DB와 트랜잭션 롤백 방식의 픽스처.
- 특성화 테스트 우선 대상(현재 동작을 그대로 고정):
  1. 부가세 계산 5곳의 결과 (A1) — 홀수 반올림 경계값 포함
  2. 외상 잔액: 거래 등록/수정/삭제, 전액·부분 결제, 결제 삭제 시 복원 (A2, A4)
  3. 연차 자동 계산(`core/leave_calc.py`)
  4. 결재선 검증과 단계 진행(`core/approval.py` 및 4개 승인 엔드포인트)
  5. 권한 판정 표: `admin`/`site_admin`/`employee` × 메뉴 권한 × 부서장 이상(`core/deps.py`)
  6. 출퇴근 기록의 날짜·시각 처리
- 프론트엔드: 현재 테스트 러너가 없다. 순수 함수(날짜·금액 변환, `remainingAmount`)만 검증하는 **vitest 도입을 제안**한다. 도입하지 않으면 `tsc`/`oxlint`/`build`와 `docs/테스트_절차서.md` 수동 점검으로 대체한다.

**승인 요청**: pytest·(선택) vitest 도입, 테스트 DB 생성(`erp_test`, 로컬 PostgreSQL에 DB 하나 추가).
**검증**: 기존 코드에서 모든 테스트가 통과해야 다음 단계로 넘어간다.
**커밋**: `test:` 접두사, 테스트만 추가.

### P1. 무해한 정리

- 미사용 import 제거: `models/project_document.py`의 `BigInteger`, `services/recurring_payment.py`의 `Client` (`main.py`의 `models` import는 유지).
- `oxlint` 경고 16개 중 안전한 것부터 정리(후크 의존성 4곳, 컴포넌트 파일 분리 3곳). 이펙트 내 setState 9곳은 동작 변화 가능성이 있어 P4에서 화면별로 처리.
- `README.md`를 실제 기능에 맞게 갱신(결재, 품의서, 세금계산서·팝빌, 부분 결제, 일정·할일 등).
- 마이그레이션 스크립트는 **삭제하지 않는다**. `scripts/README`로 목록과 적용 여부(확인 가능한 범위)를 문서화만 한다.

**영향 범위**: 낮음. **검증**: `tsc`, `oxlint`, `build`, 백엔드 import 확인.

### P2. 공통 유틸 통합 (B1, B2, A1, E4)

| 항목 | 내용 | 동작 변화 |

### P3. 백엔드 구조 개선 (E1, E2, A2)

순서(작은 것부터, 한 번에 하나의 라우터):
1. **`payments` 결제/정산 로직**을 `services/settlement.py`로 분리(`create_payment`의 부분 결제·외상 잔액 처리). 테스트 P0-2가 안전망.
2. **`transactions`**: 외상 잔액 호출 흐름 정리.
3. **결재 공통화**: `core/approval.py`에 "다음 단계 진행/최종 승인/반려" 공통 함수를 모으고 연차 → 증명서 → 품의서 → 프로젝트 문서 순으로 적용(영향이 큰 `project_documents.py`는 마지막).
4. **`project_documents.py`(1,155줄)** 를 패키지(`routers/project_documents/`: 목록·결재·팝빌·이미지)와 서비스로 분할. **API 경로와 응답은 그대로** 유지.
5. 긴 PDF 생성 함수는 레이아웃 코드라 이번 범위에서 제외(위험 대비 이득 낮음).

**동시성(A2)**: 잔액 갱신에 `SELECT ... FOR UPDATE`(행 잠금)를 적용하는 안을 제안한다. 동작 결과는 같지만 트랜잭션 방식이 달라지므로 구현 전에 다시 승인을 받는다.

**승인 요청**: 4번(대규모 분할)은 착수 전 별도 확인. **검증**: 라우터 단위로 P0 테스트 + API 응답 스냅샷 비교.

### P4. 프론트엔드 구조 개선 (E3, E5, E6, E7, E8)

- 승인/반려 공통 훅 `useApprovalActions` 추출(4개 페이지). 확인창·알림 문구는 **현재 그대로 유지**.
- 거대 페이지 분해: `ProjectDocumentsPage`, `PaymentsPage`, `ProjectDetailPage`, `ProjectDocumentFormPage`, `ClientFormPage`를 "데이터 훅 + 표/카드/모달 컴포넌트"로 나눈다. 화면 모양과 동작은 변경하지 않는다.
- `TaxInvoiceImages.tsx`의 직접 `fetch`를 `lib/api.ts` 경유로 통일.
- `api.ts`에서 401 응답 시 처리(자동 로그아웃)는 **현재 동작을 먼저 확인**한 뒤, 변경이 필요하면 [승인 필요].
- `window.alert/confirm/prompt` 45곳은 **그대로 둔다**. 커스텀 다이얼로그로 바꾸면 사용자에게 보이는 변화라 승인 사항으로 남긴다.
- 이펙트 내 setState 9곳은 화면별로 파생 상태/초기화로 정리.

**검증**: `tsc`, `oxlint`(경고 감소 확인), `npm run build`, 주요 화면 수동 점검(`docs/테스트_절차서.md` 기준). 브라우저 자동 테스트는 현재 환경에 없어 **자동 검증 불가로 보고**한다.

### P5. 보안·설정 강화 — 전부 [승인 필요] (C1~C5, C7)

| 항목 | 제안 | 영향 |
|---|---|---|
| JWT 비밀키 | 기본값이면 서버 시작 시 경고/거부(운영 모드 플래그 도입) | 기본값 사용 중인 환경은 시작이 막힐 수 있음 |
| `LOG_LEVEL` 기본값 | `DEBUG` → `INFO`(개발 `.env`에서 DEBUG 지정) | 운영 로그량 감소. CLAUDE.md의 "디버그 메시지 필수" 규칙 자체는 유지 |

| 업로드 | 파일 내용(매직바이트) 검사 추가 | 일부 파일 거부 가능 |

- 인덱스는 `EXPLAIN`으로 느린 쿼리가 확인된 경우에만 추가한다.
- 이 단계에서는 어떤 마이그레이션도 실행하지 않는다.

## 3. NFC 확장 대비 (6장 요구사항)

현재 NFC 코드가 없으므로 리팩토링 대상이 아니다. 대신 **P3 이후** 다음을 설계 문서로만 제안한다.
- 출퇴근 기록 서비스가 "인증 수단(버튼 클릭, 향후 NFC 리더)"에 의존하지 않도록 `AttendanceService.clock_in(user_id, source)` 형태의 경계를 둔다.
- 리더기별 구현은 `services/auth_devices/` 같은 어댑터 모듈에 격리한다.
구현은 신규 기능 개발이므로 이번 리팩토링에 포함하지 않는다.

## 5. 승인을 요청하는 사항

1. **테스트 도구·DB 도입** (P0): pytest, (선택) vitest, 로컬 PostgreSQL에 `erp_test` DB 추가
